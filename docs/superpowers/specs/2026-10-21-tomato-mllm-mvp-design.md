# 番茄病害识别 MVP

> 后续变更：当前默认模型已按用户要求切换为 `qwen3.8-flash`。用户随后要求展示病害可能性，具体规则见 [病害可能性展示](2026-10-21-disease-likelihood-design.md)，其中对百分比的约定替代本文原始限制。

## 已确认的范围

用户选择先实现直接调用多模态大模型的 MVP，并明确选择通义千问。沿用已讨论的微信小程序上传照片、后端识别、前端展示结果流程。当前工作目录为空，不存在既有代码或 Git 仓库。

## 产品流程

1. 原生微信小程序允许拍摄或选择一张图片，预览后可补充不超过 500 字的症状描述。
2. 点击识别后上传图片和描述，显示上传/分析状态，阻止重复提交。
3. 后端验证实际图片格式、大小和尺寸，校正旋转、压缩并删除元数据后，通过 Base64 调用 Qwen-VL。
4. 展示疑似病种、可见症状、候选原因、下一步建议和需要补充的信息。结果状态为疑似病害、未见明显病害、无法判断或非番茄图片。不显示未经校准的置信度百分比。
5. 上传错误、后端未配置、超时、限流以及模型返回无效结构均显示明确错误，用户可手动重试。模型调用不自动重试，避免重复计费。

## 技术与接口

- 前端：原生微信小程序，JavaScript / WXML / WXSS；不引入构建依赖。
- 后端：Python >=3.11，FastAPI、HTTPX、Pydantic Settings、Pillow；使用 uv 管理依赖。
- `GET /health`：返回服务状态、模型名称及是否已配置密钥，不返回任何密钥。
- `POST /api/diagnose`：multipart 图片字段 `image`，可选文本字段 `description`；返回结构化 `result` 及 `request_id`、`model`、`elapsed_ms`。
- 配置：`DASHSCOPE_API_KEY`、`QWEN_BASE_URL`、`QWEN_MODEL`；默认北京兼容接口及 `qwen3-vl-plus`，非思考模式、JSON Object 输出。所有配置仅在后端。
- 原图最大 8 MiB、最多 2500 万像素；支持实际 JPEG/PNG/WebP；分析图最长边 1600 像素。
- 模型请求超时 60 秒；小程序上传请求超时 90 秒。
- 无登录、数据库、云存储、训练、RAG、自动保存历史或问诊对话；图片与描述只用于本次请求。
- API 用于本地开发。公网发布前需要 HTTPS、微信合法域名、访问控制和配额限制；本期不公开部署。

## 模块边界

- `settings.py`：环境配置，不暴露密钥。
- `schemas.py`：诊断返回结构与状态一致性校验。
- `images.py`：真实图像解码、格式检查、尺寸限制和 JPEG 转换。
- `qwen.py`：提示词、模型 HTTP 请求、结果解析及上游错误映射。
- `main.py`：上传接口、统一错误、健康检查、HTTP 客户端生命周期。
- 小程序 `services/diagnosis.js`：上传、错误转换、取消请求。
- 小程序 `pages/index`：选图、表单、状态切换与结果展示。

## 验证与验收

使用实际图片编码与 HTTPX 模拟上游验证整条后端路径，包括合法请求、非图片、损坏图片、文件和像素限制、缺少密钥、上游失败、超时、返回无效 JSON 和状态约束。Node 内置测试运行器验证小程序网络适配和页面状态，另检查全部 JSON 配置和 JavaScript 语法。启动真实 Uvicorn 服务进行健康检查和上传错误路径 smoke test。

没有密钥时不得宣称真实模型识别已验证；没有微信开发者工具时不得宣称模拟器或真机验证已完成。
