# 病害可能性展示

用户要求在现有识别完成后增加当前疑似病害和其他病害的可能性。沿用现有 `qwen3.8-flash`、图片上传、错误处理和四种状态，密钥及服务地址不变。

## 结果约定

- 新增必填 `result.disease_candidates`，每项为 `{name, likelihood, reason}`；`likelihood` 是 0–100 的整数，表示模型自行估计的可能性，不是经数据集校准的诊断概率。
- 疑似病害时提供 1–3 项，第一项名称必须与 `disease_name` 完全一致，其他最多两项；名称不重复，按可能性从高到低排列。不为凑数编造其他病害。
- 各项是可能同时存在的独立候选，不要求合计 100%，不在后端或前端重新归一化或伪造数值。
- 健康、无法判断、非番茄时列表必须为空，不展示病害百分比。
- 原有 `possible_causes` 保留，用于解释病害以外的管理、环境等原因；新列表只列具体候选病害。

## 页面

结果中增加当前疑似病害的百分比、进度条与依据；下方展示其他候选病害及对应数值和依据。没有足够证据列其他病害时明确提示。紧邻数值标注“模型估计，未经准确率校准；仅供候选比较，各项不要求合计 100%”。

## 实施与验证

1. 扩展后端模型及模型提示词，同时在两端校验字段、数值范围、顺序、名称和状态一致性。
2. 扩展小程序结果映射和 WXML/WXSS；保留现有重试、清空旧结果和取消请求行为。
3. 验证合法候选、单一候选、无病害状态、无效百分比、重复或错配病名、错误排序；运行后端、前端和官方小程序编译检查。
4. 使用已有本地配置做一次真实接口兼容检查。测试图仅用于兼容验证，不据此声称识别准确率或百分比已校准。

此次用户功能请求替代原设计中“不显示置信度百分比”的限制；通过标注来源和未校准性质保持数值含义明确。无需增加模型训练、数据库或额外模型调用。

## 已完成的验证

- 新增测试先在旧实现上验证失败，再完成实现：后端候选相关测试有 4 项失败，前端新增行为测试有 5 项失败，分别暴露缺少字段支持、未校验字段、未映射展示字段的问题。
- 最终后端 106 项测试通过，Ruff 检查和格式检查通过；小程序 27 项测试通过，包含 JavaScript 语法、JSON 配置和所有 WXML 条件绑定检查。
- 本机微信开发者工具的官方 WXML、页面 WXSS 编译器退出码均为 0。
- 使用真实 `qwen3.8-flash` 和本地配置完成一次纯色图请求，HTTP 200、3107 毫秒，返回 `uncertain`、候选列表为空。此结果验证新字段兼容性，未验证真实病害准确率、估计值校准或模拟器/真机效果。
